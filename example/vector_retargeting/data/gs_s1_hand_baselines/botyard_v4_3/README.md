# Botyard v4.3

v4.3 是已在左右手实时入口接通的“末节连杆距离优先＋拇指掌内朝向”算法。
算法名称仍为 `botyard`，选择 `botyard_opposition:=inward` 后，启动信息、
逐帧轨迹、实时性能消息和真机日志元数据标记为 **4.3**。
`botyard_shape:=v4_2` 是其基础姿态目标名称，保留该参数以兼容已有命令。
默认选择仍为 `botyard_opposition:=v4_2`，可用于回退和对照。

## 真机测试

从仓库根目录运行，使用左手、RS485 和厂家默认 `dexhand_controller`：

```zsh
source /opt/ros/humble/setup.zsh
source ~/botyard_ws/install/setup.zsh
ros2 launch "$PWD/example/vector_retargeting/gs_s1_preview.launch.py" \
  backend:=hardware hand:=left objective:=botyard camera:=0 \
  botyard_opposition:=inward hardware_log:=true
```

`hand:=right` 可选右手。日志保存到被 Git 忽略的 `logs/hardware/`。
此命令不录制、导出视频。恢复原算法时改为 `botyard_opposition:=v4_2`。
控制器速度、力矩设置和失去目标/反馈后的停发保护保持现有配置。

## 优化方法

1. 保留 v4.2 的骨段方向、弯曲角和拇指基础朝向拟合。
2. 在源姿态、关节限位、联动、速度和完整网格碰撞约束下，先求完整末节
   STL 的接近结果。这里的对指是连杆表面靠近，不要求指腹接触区域对齐。
3. 在同一帧的接近结果上加四个独立距离保护，再优化拇指朝掌内的软偏好。
   使用 NLopt SLSQP、解析雅可比和最多三个初值。所有初值共享同一个实际
   上一指令和帧 dt，不叠加速度额度。

连续 MANO 接近权重仍为
`exp(-(MANO_gap/(0.15*MANO_palm_width))**2)`。
距离保护为 `alpha_i * (gap_i - first_gap_i) <= 0.1 mm`，其中
`alpha_i = weight_i/(sum(weights)+1e-12)`。
这不是相对独立历史轨迹、对每根手指都适用的原始 0.1 mm 保证；两个控制器
的上一指令不同，必须通过完整因果回放比较最终行为。

掌内参考由 CAD 零位拇指基座方向和当帧拇指弯曲生成，不固定实际关节角。
朝向系数为 0.2，关节锚定系数为 0.03，角度单位为 20°。
锚定系数独立于接近权重，避免弱接近证据也引起明显动作。
四指 J4 保持自由。没有手势分类、越过食指阈值或指腹中心位置目标。

## 验证与限制

完整同输入回放覆盖 example 621 帧、自录 395 帧（330 帧跟踪有效）和横扫
149 帧。源姿态、几何、关节范围和速度检查通过。下表为预定窗口中位数；
角度相对上述掌内参考，不能理解为相对 MANO 的方向误差。

| 对指窗口 | 末节间距 v4.2 / v4.3，mm | 掌内参考偏角 v4.2 / v4.3，° |
| --- | ---: | ---: |
| Example 食指 | 1.181 / 1.620 | 46.88 / 20.38 |
| Example 中指 | 1.774 / 1.696 | 16.76 / 5.21 |
| Example 无名指 | 3.015 / 3.074 | 59.58 / 56.40 |
| Example 小指 | 18.493 / 18.574 | 62.94 / 61.55 |
| 自录食指前段 | 1.616 / 1.715 | 34.33 / 30.56 |
| 自录食指后段 | 1.482 / 1.578 | 28.04 / 25.14 |

小指可达性和所有手势的朝向仍未全部解决。数值失败保留已评估的可行候选，
多初值不保证全局最优。MANO 几何接近不等于触觉确认。

新增朝向阶段增加计算量；当前版本尚不能视为高频、低延迟求解器。实时路径
仍限制在一个在途任务，丢弃超过 0.5 秒或属于上一次跟踪周期的结果。真机
日志用于区分视觉、求解、指令年龄和硬件采样，不能仅凭角度误差推断电机延迟。

历史实验和详细窗口见 [调研与回放记录](../botyard_v4_2/opposition_guidance_notes.md)。
原始录像、模型、逐帧数据和性能日志留在本地，由忽略规则排除。
